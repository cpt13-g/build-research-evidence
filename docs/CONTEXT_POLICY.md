# 高质量实验与上下文使用协议

实验设计质量、比较公平性、证据完整性和独立审计优先。节省 Token 的对象是重复背景、机械往返和无新增信息的输出；不得因此缩减必要候选设计、Seed、统计检查、反证分析或人工 Gate。

## 角色视图与恢复

默认通过 `tools/context_view.py` 读取权威状态的只读投影。视图即时生成，不建立第二份决策状态，不改原始证据或现有授权门禁。

- Orchestrator：保留研究主线、Claim/EQ、所有活跃任务、预算、Gate、当前方法和未解决风险；历史队列只显示有限条目及明确的省略数量。
- Runner：完整实验卡、完整评价合同，以及当前实验的授权状态、依赖、预算与执行约束。
- Auditor：完整实验卡、完整评价合同、经完整性校验的 Run Manifest 和原始材料索引。首轮不读取全局 Claim 状态、总控下一动作、历史解释或总控聊天。
- Venue Audit：研究问题、Claim/EQ、Gate 和当前证据文件引用；按实际缺口读取证据矩阵与结果。

视图包含 revision、源文件哈希和协议文件哈希。源文件有变化、新会话、上下文压缩后缺失规则时重新建立视图；同一上下文中确认已读且哈希未变的协议可复用。哈希目录本身不表示协议内容已读。新会话仍需读取公共协议、交接协议和本协议，以及与当前阶段有关的专项协议。

原始 `research/research_state.yaml` 仍是唯一决策状态源；由工具读取和校验后投影，等价于按职责读取该状态。完整状态可用 `python tools/state_manager.py show --full`，精确字段可用 `python tools/state_manager.py show --field candidate_registry`。

`Research Spine.md` 是设计规范的最高依据；常规运行依照已维护的正式协议，涉及 L1 边界、规范冲突或协议未覆盖的科学决策时按相关章节查阅，避免反复全文加载。

任何省略都不是“已解决”或“无关”。选择候选、调整依赖、重开搜索、判断假设风险、通过 Gate 或冻结证据前，必须展开相关候选、失败/负面结果和未完成证据。摘要无法支持判断时，读取原文；不能用摘要代替必要的科学审阅。

## 按证据问题交接

一次 Runner 任务可以连续完成同一批准实验卡内的多个 Seed、必要检查及有限工程修复，保留每次尝试的日志与清单。多张独立实验卡仍分别批准、激活、记录预算和输出 Run Manifest。

路径、依赖安装、语法等明确的 F1 工程故障由 Runner 在批准范围和调试预算内处理。遇到科学机制、超参数公平比较、数据划分、评价协议或停止条件变化，以及原因不确定时，交回 Orchestrator；有科学解释价值的失败仍须审计和记录。

一次 Auditor 调用可审阅一组预先批准且属于同一证据问题的运行。每个运行仍须单独核验清单并绑定 Result Record，不能只留均值、最好 Seed 或单个代表记录。可以在同一实验卡和完整运行记录中分析多 Seed 结果，不得因节省调用而降低 Seed 要求。

首轮审计使用新隔离上下文和原始证据包；若宿主不能隔离，沿用 FULL_CONTEXT_EXCEPTION 规则，不得声称盲审已经完成。工程故障修复不要求每个报错都启动科学审计，但正式证据、候选科学淘汰、F2 诊断和方法迭代仍需独立审计。

## 工具检查、日志与历史

Schema、哈希、授权、预算和依赖的机械检查交给现有工具执行。通过检查仅证明对应字段或文件完整，不能代替科学有效性、公平性和收敛性判断。

日志先按文件和行号读取相关窗口，异常、曲线、Seed 差异、数据泄漏及关键检查应追溯原始材料。`excerpt` 返回行号、总行数、截断位置和来源哈希；截断内容不能当作已经审阅。证据不足时扩大窗口或直接读取完整文件。

`history` 流式检索事件，支持实验 ID、事件类型和向前翻页。检索过滤只缩小阅读范围，不能删除或忽略负面、空结果、边界和失败记录。原始日志与记忆完整保留。

长训练使用进程等待或完成通知；无新输出时减少重复轮询和重新规划，不在等待中反复调用专业角色。常规汇报只说明新增发现、证据变化、决定和下一步；Gate、关键诊断和最终报告保持必要深度。

## 验证节约是否影响质量

先验证完整科研流程和门禁，再比较相同任务下的上下文字符/字节数、重复读取和角色调用。项目不能读取宿主的真实 Token 计费时，字符数仅作输入规模指标，不能宣称实际 Token 节省比例。不要为了满足 Token 上限中断必要的设计和审计；先消除重复，必要时继续投入并记录原因。
